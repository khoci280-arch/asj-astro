## Font Awesome → local SVG sprite (migration completed, uncommitted)
User said "tolong lanjutkan" — picked up the half-finished refactor that was
already in the working tree (ui/Icon.tsx, icons/sprite.svg, theme.css,
store/theme.ts, Toast portal). What I did:

- Migrated all 348 `<i class="fa…">` to `<Icon name="…" />` across 40 files.
  Static classes by throwaway codemod (326); the other 36 by hand (template
  literals, ternaries, preact `h()` calls, and RirekishoBuilder which builds
  markup as an HTML string so it needs literal `<svg><use href="#fas-x"/>`).
- **Bug found:** `Icon` composed `#fas-<name>` itself, but whatsapp/instagram/
  tiktok only exist as `fab-` → they never rendered. Fixed by having
  `npm run icons` also emit `src/icons/sprite-map.ts` (name→id manifest) and
  having Icon read it. The `brand` prop is gone.
- **Bug found:** `fas-print` was absent from the sprite — RirekishoBuilder's
  `<use href="#fas-print">` lives inside a JS string so the scanner missed it.
  Added scanner rule 5 + a post-check in build-icon-sprite.mjs that fails
  hard, plus `src/components/ui/Icon.test.ts` (5 tests) asserting the inverse.
  Verified the guard actually fires by corrupting the map on purpose.

Result: 152 glyphs, 81.5 KB inline → 24.1 KB gzip; zero cdnjs/googleapis
references left in dist/; sprite-map lands in ONE shared chunk.
